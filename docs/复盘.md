# 决策助手产品/技术复盘

## 一句话

决策助手是一个完整闭环的 AI 决策作品：输入纠结、AI 拆解、生成低后悔建议、事后复盘，并沉淀个人决策画像。

## 为什么做

最初目标是做一个真正可用的 AI 小产品，而不是只停留在 demo。它需要具备：

- 可公开访问的 Web。
- 可演示的移动 App。
- 真实账号体系。
- 服务端 AI 代理。
- 数据库持久化。
- 有审美记忆点的角色和界面。

后续判断发生变化：消费 AI 已经很红海，AI 能力本身不稀缺，真正稀缺的是分发和人群。因此本项目收敛为作品集/简历展示，不再重押规模化增长。

## 产品闭环

1. 用户写下一句纠结。
2. AI 整理成决策草稿。
3. 用户确认选项。
4. AI 生成低后悔建议。
5. 用户完成复盘。
6. 复盘数据进入个人画像。

这个闭环比“一次性问答”更像产品，因为它有状态流转和数据沉淀。

## 技术选型

- Next.js：负责 Web、SEO、服务端 API、Vercel 部署。
- Expo：负责 Android/iOS 原生端展示，不替代 Web。
- Neon + Prisma：快速获得可迁移、可维护的关系型数据层。
- DeepSeek：通过服务端代理调用，避免把 key 放到前端或 App。
- SecureStore：App 登录 token 存储。

最终架构不是 Expo-only，也不是 PWA-only，而是 **Next Web + Expo App + shared core 方向**。

## 主要踩坑

- PWA 安装体验不稳定，尤其移动端浏览器只像“快捷方式”，不适合作为 App 展示主路线。
- Expo Go / SDK 版本要谨慎固定，本项目保持 Expo SDK 54。
- 一开始没有账号体系时，数据全局共享，是隐私和可信度硬伤。
- Web 和 App 若完全分开写，类型和 API 契约容易漂移；后续应抽 `packages/core`。
- UI 一致性不等于共享组件。真正要共享的是 tokens、角色规范、业务逻辑和 API 契约。

## 当前成果

- Web 与 App 共用一套账号和后端 API。
- 匿名用户可以完整使用，登录后历史跨端可见。
- AI key 与数据库连接串只在服务端。
- 小羊角色系统已覆盖 idle / thinking / happy / celebrate。
- 首页提供 Android APK 下载入口和二维码。

## 作品价值

这个项目适合作为简历/面试里的全栈 AI 产品案例，因为它能讲清：

- 产品判断：从想做增长到收敛作品展示。
- 技术架构：Next + Expo + Prisma + Neon + AI proxy。
- 安全边界：服务端 key、身份隔离、匿名与登录数据 claim。
- 跨端取舍：Web 保留 SEO/分发，Expo 保留原生体验。
- 设计打磨：小羊角色系统和克制动效。
