# 决策助手产品/技术复盘

## 做了什么

决策助手是一个完整闭环的 AI 决策作品：用户输入一句纠结，AI 拆成背景、选项、风险和低后悔行动；用户做完选择后再复盘，复盘结果沉淀成个人决策画像。

这不是一次性聊天 demo，而是一个有状态流转的产品闭环：

1. 输入纠结。
2. AI 整理决策草稿。
3. AI 生成报告与建议。
4. 用户记录最终选择。
5. 用户复盘结果和后悔分。
6. 系统更新个人画像。

## 技术选型

- **Next.js**：承担 PC Web、移动 Web、服务端 API、Vercel 部署和 SEO 入口。
- **Expo SDK 54**：承担 Android/iOS 原生体验展示，不替代 Web。
- **Neon Postgres + Prisma**：承载账号、决策、复盘和画像数据。
- **DeepSeek 服务端代理**：AI key 只放服务端，Web/App 都不接触密钥。
- **账号体系**：Web 用 httpOnly cookie，App 用 Bearer token + SecureStore；匿名用户用 `anonId`，登录后 claim 匿名数据。

最终架构是 **Next Web + Expo App + shared core 方向**：Web 保留分发和服务端优势，Expo 保留原生端展示能力。

## 踩坑

- **SDK**：Expo 版本要固定，本项目保持 SDK 54，避免 Expo Go / 依赖版本来回漂。
- **部署**：Vercel 负责 Next Web 和 `/api/*`，Neon 负责数据库；本地和生产都必须通过 env 管理 `DATABASE_URL` 和 `DEEPSEEK_API_KEY`。
- **账号体系**：早期没有 userId/anonId 隔离时，数据是全局共享的，这是隐私和可信度硬伤；P0 后已补账号、session、匿名 claim 和数据隔离。
- **跨端同步**：App 不能直连 Neon 或 DeepSeek，必须走同一套 Next API；否则会出现 Web/App 数据和逻辑漂移。
- **PWA**：移动端安装体验更像快捷方式，不适合作为“原生 App 展示”路线，因此放弃 PWA，保留 Next Web + Expo App。

## 产品判断

AI 能力已经商品化，“能生成分析”本身不是壁垒。消费 AI 赛道很红海，真正稀缺的是分发、人群和具体场景。

所以本项目不继续重押规模化增长，而是收敛为作品集/简历项目：展示完整产品闭环、账号体系、跨端架构、安全边界和 UI 打磨。以后如果要做商业化，应先找到自带受众的细分场景，再复用这套技术骨架。

## 面试可讲亮点

- 从 0 到线上：Web、API、数据库、AI 代理、账号体系、Expo App。
- 隐私与安全：服务端 key、httpOnly cookie、Bearer token、匿名与登录数据隔离。
- 产品闭环：不是只调 LLM，而是有复盘、画像和数据沉淀。
- 架构取舍：没有盲目 Expo-only，也没有硬上 PWA；根据分发和展示目标选择 Next + Expo。
- 设计记忆点：小羊角色系统，温暖但克制，覆盖 idle / thinking / happy / celebrate 四态。
